Sources

What it reads

Google Calendar, Gmail and Google Tasks are the core of the brief. Canvas, weather and news headlines are optional extras. Every source is read, never written to.

  • calendar.readonly

    Google Calendar

    Today's and tomorrow's events from the primary calendar, chosen calendars, or every calendar shown in Google Calendar. Cancelled events, declined invitations and working-location entries are skipped.

  • gmail.readonly

    Gmail

    By default, unread inbox mail from the last two days, leaving out Promotions, Social and Forums. Only the sender, subject, Google's short preview, labels, received time and thread ID are fetched, never full message bodies.

  • tasks.readonly

    Google Tasks

    Overdue tasks, tasks due within three days, and a few tasks with no due date. Completed tasks are skipped.

  • OptionalOff by default

    Canvas LMS

    Planner items for the next seven days and missing submissions, read with a personal access token. The brief warns seven days before the expiry date the owner enters for that token.

  • OptionalNo API key

    Weather

    Current conditions and the forecast from Open-Meteo, which receives only the coordinates, the time zone and the units from the app's configuration, never any Google data.

  • OptionalOff by default

    News headlines

    A few headlines from plain RSS or Atom feeds. Feeds that declare a DTD are refused, and so are feeds larger than 2 MB.

Up to three Google accounts can be connected: two personal accounts and an optional school account, which is off by default.

How it works

From a 05:00 timer to one finished page

Plain code does the fetching, merging and arithmetic. A small language model on the same computer only writes the short summary at the top.

  1. 05:00

    A timer starts the run

    A scheduled timer on the owner's computer starts the brief every morning. If the computer was off at 05:00, it runs once as soon as the computer is back on.

  2. Read

    It collects the day, read-only

    It asks Google for events, recent unread mail and open tasks for each connected account, then reads any optional sources that are turned on. If one source fails, the rest of the brief is still made.

  3. Merge

    Code puts it in order

    The same invitation on two calendars is shown once, overlapping busy events are flagged as conflicts, and relative dates such as “due tomorrow” and every count are computed by code. Each item gets a short ID, like E1 for an event or T1 for a task.

  4. Summarize

    A local model writes the overview

    A small model running through Ollama on the same computer writes a two-to-four-sentence overview and up to three priorities. Any item ID it gives is checked against the real list, and made-up IDs are discarded. If the model is unavailable, the brief is made without it.

  5. Done

    One page, ready to read

    The brief is saved as private files on the computer, as a web page and a Markdown copy. Dated copies are deleted after 30 days by default while the app runs. If the owner turns it on, a phone notification with the day's counts follows.

Read-only by design

What it cannot do

Some limits are enforced by Google, because the app only holds read-only permissions. Others are choices made in the code.

Cannot, by permission

With only read-only access, Google does not let it:

  • Send, reply to, forward or draft email
  • Delete, archive, label or mark messages as read
  • Create, change or delete calendar events
  • Create, complete or delete tasks

Does not, by design

Some things are left out on purpose. It does not:

  • Download full email bodies or attachments
  • Contain any code that writes to Google, Gmail or Canvas
  • Send data to the developer or to a cloud AI service
  • Have ads, tracking, user accounts or a server run by the developer

Google permissions

Three permissions, all read-only

These are the only Google permissions it requests. It never asks for send, modify, compose, delete or write access.

Data handling

Google data is processed on the owner's computer

A short summary. The privacy policy has the details.

  • Processed locally

    Google data is processed only on the computer the program runs on. It is not sent to the developer, and the developer runs no servers.

  • Summarized on-device

    The language model runs on that same computer. No cloud AI service sees the data, and it is not used to train AI models.

  • Private, owner-only files

    Each brief is saved as owner-only files, and dated copies are deleted after 30 days by default while the app runs. Login tokens are kept in owner-only files and are never printed or logged.

  • Never sold, no advertising

    Nothing is sold or used for advertising, and nothing is sent to the developer. Two optional extras, both off by default, can send information beyond the computer: a phone notification through a server the owner chooses, with only counts by default, and a web viewer the owner can make reachable on their home network, for example from their phone.
