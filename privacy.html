Privacy policy

Last updated: 2026-10-07

This policy explains which Google user data Morning Brief Ultra Pro Max Tier reads, what it does with that data, where the data is kept, and how to remove it. In short: the app is read-only, and Google data is processed only on its owner's computer. It can leave that computer only through two optional features the owner turns on, described in section 6.

In short

  • The app only views data. It cannot send, change or delete anything in a Google account.
  • Google data is processed only on the owner's computer, including by an AI model that runs there. It is not sent to the developer or to a cloud AI service. The only ways Google data can leave the computer are the optional phone notification and web viewer, and only if the owner turns them on.
  • Nothing is sold, shared for advertising or used to train AI models.
  • Dated copies of the daily summaries are deleted after 30 days by default while the app runs, and access can be revoked at any time.

1. Who runs it and what this policy covers

Morning Brief Ultra Pro Max Tier (“the app”) is a personal, self-hosted program. It is built and run by an individual developer for their own use, and it runs only on its owner's own computer. There are no user accounts, no sign-ups and no servers run by the developer.

This policy covers how the app handles data from the Google accounts connected to it (up to three per installation), data from the optional non-Google sources it can read, and this website. In this policy, “you” means the person whose accounts are connected to the app, which in practice is its owner.

2. Google user data the app accesses

The app asks Google for three read-only permissions: Google Calendar calendar.readonly, Gmail gmail.readonly and Google Tasks tasks.readonly. Within those permissions, it uses only the following. For Gmail, the app asks Google only for the message details listed below, never the message body. For Calendar and Tasks, Google returns each event or task as a whole record, so its replies can include other details, such as an event's description or guest list; the app discards those in memory and never stores, shows or passes them to the AI model.

Google Calendar calendar.readonly

What is read
Each event's title, start and end time, location, video-call link, link to the event in Google Calendar, whether it is marked busy, and your own reply status, so that events you declined can be skipped. Also the list of calendars on the account and their names, used to choose which calendars to read and to label events.
Which items
By default, today's and tomorrow's events, from the primary calendar, calendars you name, or every calendar shown in Google Calendar. Cancelled events, events you declined and working-location entries are skipped.

Gmail gmail.readonly

What is read
For each message: the sender, the subject, Google's short preview of the message (the “snippet”), its labels (unread, important, starred), the time it was received, and its thread ID, which is used to build an “open in Gmail” link. Also the number of unread messages in the inbox.
Which items
By default, unread inbox mail from the last 2 days, excluding the Promotions, Social and Forums categories; one message per conversation and up to 12 per account. Full message bodies and attachments are never downloaded.

Google Tasks tasks.readonly

What is read
Task titles, due dates, short notes, and the name of the list each task is on.
Which items
By default, overdue tasks, tasks due within 3 days, and up to 5 tasks with no due date. Completed tasks are skipped.

Account email address

What is read
The email address of the signed-in Google account.
Why
It is stored next to that account's login so the owner can see which connected account is which, and it is used in “open in Gmail” links so they open the right account.

The app does not request permission to send, modify, compose or delete anything in a Google account, and it contains no code that writes to Google.

3. How the data is used

Google user data is used for one purpose: to build the owner's own daily brief. Specifically, it is used to:

  • list the day's events with their times and places, and flag events that overlap, including across accounts;
  • show an invitation only once when it appears on more than one calendar;
  • show overdue and upcoming tasks with relative dates such as “due tomorrow”;
  • show recent unread mail by sender, subject and preview, with a link to open it in Gmail;
  • compute the counts at the top of the page, such as events today and unread messages;
  • give the local AI model the material for the short written summary (see section 4).

Google user data is not sold, not used for advertising, not used to train AI models, and not used for anything other than the brief. It is processed only on the owner's computer and is not sent to the developer.

4. The local AI model

The short written summary at the top of each brief is produced by a small language model that runs on the same computer as the app, through Ollama (by default, the model qwen3.5:4b). The app does not use any cloud AI service.

  • The model receives a compact text version of the day's items, such as events, tasks, and the sender, subject and preview of recent emails.
  • It writes only prose: an overview of two to four sentences and up to three priorities. Each priority can name the item it is about by its short ID. The code checks every ID against the real list of items and removes any it cannot find, so a priority is never attached to an item that does not exist.
  • Times, dates, counts, links and the order of items on the page always come from code, never from the model.
  • Text from emails, calendars and websites is treated as untrusted. The model is instructed to ignore any instructions that appear inside that text.
  • The model is loaded only for the app's run and unloaded about two minutes later.
  • Your data is not used to train or improve any AI model.
  • If the model is missing, slow or not working, the brief is still made, without the written summary.

5. Storage and retention

Everything the app keeps is stored on the owner's computer. Nothing is stored on servers run by the developer, because there are none.

Login tokens
Google login tokens, and the Canvas token if Canvas is used, are stored in files only the owner's user account can read (file permissions 600, in a folder with permissions 700). They are never printed or written to logs, and they are kept until the owner deletes them. Revoking access makes them stop working.
Account email address
Stored next to each login, as described in section 2.
Daily briefs
Each brief is saved as a web page (a “latest” page plus a dated copy) and Markdown copies of both, as owner-only files. Each run replaces the “latest” copy and deletes dated copies older than 30 days (the owner can change that period). If the app stops running, saved briefs stay until the owner deletes them.
Run log
Each run writes a short status line per source (account name, ok or failed, number of items) to the computer's system log. It contains no email, event or task content and is never sent anywhere.

The owner can delete any of these files at any time.

6. Sharing

Google user data is not sold, rented or shared, and it is not sent to the developer. There are two exceptions, both optional, off by default and controlled by the owner:

  • Optional phone notification. If the owner turns it on (it is off by default), a short message is sent through a notification server the owner chooses, using ntfy. By default it contains only counts, for example: “3 event(s) today, 1 overdue or missing, 2 due today, 7 unread.” The owner can choose to also include the short written summary, which may mention items from their calendar, mail or tasks.
  • Optional web viewer. Off by default. It lets the owner open their own brief in a browser and serves nothing but the brief pages. By default it can be reached only from the same computer. The owner can choose to make it reachable from other devices on their home network, such as their phone. It has no password: anyone on that network who can reach it, or who has its secret link if the owner sets one, can open the brief pages.

7. Other services the app contacts

Besides Google, the app can contact the services below. Apart from Ollama, which runs on the owner's computer and receives the day's items so the local model can write the summary (section 4), and the optional notification described in section 6, none of them receive Google user data.

  • Open-Meteo (weather, optional). Receives only the coordinates, the time zone and the units from the app's configuration, never any Google data. No API key or account is used.
  • Canvas LMS (optional, off by default). The app reads planner items for the next 7 days and missing submissions from the owner's Canvas site, with read-only requests and a personal access token.
  • RSS and Atom feeds (optional, off by default). The app downloads the feeds the owner lists, with plain read-only requests.
  • ntfy (optional, off by default). Delivers the phone notification described in section 6.
  • Ollama. Runs on the owner's computer, as described in section 4.

8. This website

This website is a set of static pages hosted on GitHub Pages. It sets no cookies and uses no analytics, tracking, scripts, web fonts or other outside resources. GitHub, which hosts the site, may log visits under its own privacy statement.

9. Security

  • Sign-in uses Google's OAuth flow for desktop apps with PKCE, and requests only the three read-only permissions listed in section 2.
  • The app contains no code that writes to Google, Gmail or Canvas.
  • Tokens are stored in owner-only files and are never printed or logged.
  • Brief pages are inert: no JavaScript, nothing loaded from the internet, all text escaped, and only plain http(s) links.
  • The optional web viewer, off by default, is read-only and serves only the brief pages. By default it listens only on the computer itself (127.0.0.1). It sends strict security headers and never logs its optional secret path.
  • The app's automated tests run against a fake, local stand-in for Google, Canvas, Open-Meteo and Ollama that refuses to connect to the real internet, so tests never touch a real account. No real credentials are used in them.

No system is perfectly secure. The app's safety also depends on the computer it runs on, which is the owner's responsibility.

10. Your choices

  • Revoke the app's access at any time at https://myaccount.google.com/permissions. After that, the app can no longer read that account.
  • Delete the token files on the computer to remove the app's login for an account.
  • Delete saved briefs whenever you like, or change how many days they are kept.
  • Leave the phone notification off, or keep it to counts only.
  • Leave the web viewer off, or keep it reachable only from the computer itself.
  • Leave the optional sources (Canvas, weather and news headlines) off.
  • Stop using the app entirely, as described in the terms of service.

11. Google API Services User Data Policy

Limited Use disclosure

Morning Brief Ultra Pro Max Tier's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

In practice, this means Google user data is used only to provide the brief to the owner, is not transferred to anyone except as described in section 6, is not used for advertising, and is not used to train AI models.
